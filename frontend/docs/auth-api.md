# 인증 API

원본 명세: `api-spec.csv` (사용자 제공). 로그인 POST `/auth/login`, 회원가입 POST `/auth/signup`.

사용자가 제공한 상세 명세를 적용했습니다. 서버 주소는 아직 미정입니다.

- 회원가입: POST `/auth/signup`, JSON `{ phone, password, name }`. 화면의 닉네임을 `name`으로 전송합니다.
- 성공: 201, `{ user_id: number, phone: string, name: string, created_at: string }`.
- 오류: 400 입력값 형식, 409 가입된 전화번호, 500 서버 오류.
- 실제 개발 서버 OpenAPI 확인 결과: phone 10~20자, password 8~100자, name 1~50자이며 필드 검증 실패 시 422가 반환됩니다. 프론트에서도 가입 비밀번호/닉네임 길이를 검사하고 422 필드별 오류를 표시합니다.
- 로그인: POST `/auth/login`, JSON `{ phone, password }`.
- 성공: 200, `{ access_token: string, refresh_token: string, token_type: "bearer", expires_in: number }` (만료 시간 단위: 초).
- 오류: 400 입력값 형식, 401 전화번호/비밀번호 불일치, 500 서버 오류.

비밀번호 확인은 클라이언트에서만 검사하고 전송하지 않습니다.
로그인 응답은 런타임 검증 후 메모리 세션으로 보관합니다. 앱 재시작 시 유지되지 않습니다. 보안 저장소, 토큰 재발급(명세 미제공), 홈 화면 이동은 추후 연결합니다. 비밀번호/토큰은 로그에 출력하지 않습니다.

`frontend/.env`에 `EXPO_PUBLIC_API_URL`을 지정하고 Expo를 재시작하세요. 휴대폰에서 접속 가능한 서버 주소여야 합니다. `.env.example`을 참고하세요.

## 로그아웃 (사용자 제공 상세 명세)

- POST `/auth/logout`, Authorization: Bearer Access Token, JSON `{ refresh_token: string }`.
- 200: `{ message: "로그아웃되었습니다." }`. 성공 응답 확인 후 메모리 토큰과 관심 상품 상태를 지우고 화면 기록을 정리해 로그인으로 이동합니다.
- 401: 인증 만료/유효하지 않은 토큰 안내 후 로컬 세션을 지우고 로그인으로 이동합니다. 서버 토큰 폐기 성공으로 표시하지 않습니다.
- 500/네트워크/비정상 응답: 세션을 유지하고 오류를 표시해 재시도할 수 있게 합니다.
- 개발 미리보기 등 로그인 세션이 없는 경우 서버에 빈 토큰을 보내지 않고 로그인으로 돌아갑니다.
- 중복 클릭을 막고 토큰은 로그에 출력하지 않습니다. 실제 서버 검증은 서버 주소 제공 후 가능합니다.

## 회원가입 후 이용 유형 선택

입력 화면에서 다음을 누르면 고객/상인 선택 단계로 이동합니다. 고객은 바로 완료할 수 있고, 상인은 가게 이름과 지도 위치가 필수입니다.
완료 시 회원가입 → 로그인 → 온보딩 PATCH 성공 후 홈으로 이동합니다. 가입 성공 후 로그인 등이 실패한 경우 완료 재시도 시 회원가입 요청을 반복하지 않습니다.
역할/가게명/선택한 시장 ID는 서버에 저장하고, 사용자 ID별 기기 캐시에는 가게 좌표와 서버 응답도 보관합니다. 비밀번호는 기기 저장소나 라우트 파라미터에 저장하지 않습니다.
사용자 상세 명세에 따라 PATCH `/users/me/onboarding`을 호출합니다. Authorization Bearer 토큰과 JSON role(CUSTOMER/MERCHANT), market_id(선택), store_name(선택)을 보냅니다. 지도 좌표는 명세에 없어 보내지 않으며 소속 시장은 주변 시장 API가 반환한 실제 ID를 선택해서 전송합니다. 고객은 role만 전송합니다. onboarding_completed=true와 응답 role을 확인한 후에만 홈으로 이동합니다. 400/401/404/409/500 오류를 안내하고 계정이 생성된 이후에는 회원가입을 반복하지 않습니다.
가게 위치는 탐색 위치와 별도로 보관해 홈의 탐색 기준을 덮어쓰지 않습니다.

## 상인 홈 역할 표시

온보딩 성공 응답의 role을 현재 메모리 세션에 반영합니다. 홈 탭에서 MERCHANT인 유효 세션에만 상품 등록/수정하기 버튼을 표시합니다. 로그아웃 또는 다른 계정 로그인 시 이전 역할은 유지하지 않습니다.

재로그인 역할 조회는 CSV의 GET /users/me를 사용합니다. Bearer 인증과 최상위 role(CUSTOMER/MERCHANT) 응답은 상세 명세가 없어 임시 연동 가정이며 확정 명세가 아닙니다. 조회 실패 또는 알 수 없는 역할이면 로그인은 유지하고 상인 버튼을 숨깁니다. 서버 상세 응답 확인이 필요합니다. 홈 버튼은 음성 상품 관리 화면으로 이동합니다.

## 음성 상품 관리 (사용자 제공 상세 명세)

홈의 상인 버튼은 /voice 화면으로 이동합니다. expo-audio로 권한을 요청한 뒤 녹음하며, 실제 음량으로 파형을 표시합니다. 마이크를 다시 누르면 녹음을 종료하고 전송합니다. 취소/화면 이탈/백그라운드 전환으로 종료한 녹음은 전송하지 않습니다.

모든 요청은 multipart/form-data의 audio_file 파일을 전송합니다.
- 등록: POST /voice/product-registration, 성공 201. 추가 ID 없음.
- 수정(할인 포함): POST /voice/product-update, product_id 필수, 성공 200.
- 삭제: POST /voice/product-delete, product_id 필수, 성공 200.
- 품절: POST /voice/sold-out, product_id 필수, 성공 200.
- 할인 종료: POST /voice/sale-delete, sale_id 필수, 성공 200.

상품/할인 선택 API의 상세 응답이 없어 현재는 작업 변경 후 실제 ID를 직접 입력합니다. 음성에서 ID를 추정하지 않습니다. 수정 응답의 price는 기본 가격이며 discount_rate/discount_price는 할인 없음일 때 null입니다.

인증 실패와 상인 권한 오류는 명세에 있지만 인증 헤더 형식은 명시되지 않았습니다. 기존 세션의 Bearer 토큰 사용은 임시 연동 가정으로 서버 확인이 필요합니다. 오디오 코덱/확장자 및 크기 제한도 미확정입니다. 현재 네이티브는 m4a, 웹은 브라우저 녹음 형식을 전송합니다. 서버 응답 지연/통신 오류 시 자동 재전송하지 않으며 중복 처리를 막기 위해 상품 상태 확인을 안내합니다. 마이크 동작과 서버 음성 분석은 실기기 검증이 필요합니다.

## 음성 결과 화면 및 사진 선택

음성 API의 성공 응답에서 product_name, unit, price가 있으면 결과 화면에 표시합니다. 삭제/품절/할인 종료 응답에는 이름과 가격이 없으므로 해당 값은 정보 없음으로 표시하며 임의로 생성하지 않습니다. 목적은 호출한 작업을 기준으로 신규등록 / 상품 정보 수정 / 상품 삭제 / 품절 처리 / 할인 종료로 표시합니다. 별도의 AI 의도 판별 응답은 명세에 없습니다.

현재 음성 API는 분석 전용이 아니라 호출 즉시 상품을 변경합니다. 따라서 결과 화면의 이대로 등록하기는 홈으로 돌아가며 동일한 음성 API를 재호출하지 않습니다. 확인 후 최종 등록하는 흐름에는 별도 분석/확정 API 명세가 필요합니다. 다시 등록하기는 새 녹음 화면으로 이동하며 이전 요청을 취소하거나 되돌리지 않습니다.

사진과 함께 등록하기는 시스템 사진 선택기로 이미지 한 장을 선택하고 POST /images에 multipart/form-data의 image_file과 음성 처리 결과 product_id를 전송합니다. 201 응답의 image_id/product_id/image_url을 확인한 뒤 연결 완료를 표시합니다. 400/401/403/404/413/415/500 및 통신 오류를 처리하고 중복 클릭을 막습니다. 업로드 성공 후 추가 업로드 버튼을 숨깁니다. 인증 헤더는 기존 Bearer 사용 가정입니다. 사용자가 제공한 이미지 상세 명세를 적용했으며 확인 전 분석 전용 흐름의 백엔드 요청안은 voice-confirmation-api.md를 참고하세요.
