# 음성 분석 후 사용자 확인 흐름 — 백엔드 요청안

현재 POST /voice/product-registration 등은 음성을 분석하는 동시에 상품을 변경합니다. 사용자는 결과를 본 뒤 저장 여부를 결정하고 싶으므로 아래 역할을 분리해야 합니다. 아래는 제안이며 확정 API 명세가 아닙니다.

1. 음성 분석: audio_file과 필요한 대상 ID를 받아 상품을 생성·수정·삭제하지 않고 분석 결과를 반환합니다. 결과에는 작업 목적(신규등록/상품 정보 수정/상품 삭제/품절 처리/할인 종료), 상품명, 수량·단위, 기본 가격, 할인 정보, 대상 상품/할인 ID가 필요합니다. 누락된 정보나 모호한 대상도 구분해 주세요.
2. 최종 반영: 사용자가 확인 버튼을 누를 때 분석 결과를 실제로 반영합니다. analysis_id 같은 서버 발급 식별자로 분석 결과를 연결하고 권한·대상 상태를 재검증해 주세요. 중복 클릭/재시도로 같은 작업이 두 번 반영되지 않도록 멱등성 처리가 필요합니다.
3. 취소/다시 녹음: 분석 결과만 폐기하고 상품 데이터는 변경하지 않습니다. 분석 결과의 보관 기간·만료 및 취소 방식도 정해 주세요.
4. 사진: POST /images는 신규 등록 전 product_id 없이 업로드할 수 있으므로 최종 반영 API에서 image_id를 연결할 수 있어야 합니다. 또는 최종 반영 성공 후 반환된 product_id로 사진을 업로드할 수 있습니다. 미사용 이미지 정리 정책도 필요합니다.

분석 API/최종 반영 API의 경로, 메서드, 인증, 필드, 오류 응답을 확정해 공유해주세요. 기존 변경 API에 분석 전용 모드를 추가하는 설계도 가능하지만 분석 단계에서 상품 데이터가 변경되지 않아야 합니다. 현재 응답만으로는 삭제·품절·할인 종료의 상품명/가격이나 AI가 판별한 목적을 알 수 없습니다.
