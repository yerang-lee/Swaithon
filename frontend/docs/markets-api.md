# 주변 시장 API

사용자 상세 명세: GET `/markets/nearby`.
Query: latitude, longitude (필수 Float), radius (Integer, 미터, 기본 5000), limit (Integer, 기본 10).
응답 200: `{ markets: [{ market_id, market_name, address, latitude, longitude, distance, image_url }] }`. distance는 미터.
400은 위치/반경 오류, 404는 결과 없음, 500은 서버 오류로 처리합니다.

선택 반경을 km에서 m로 변환합니다. 명세 응답을 검증하고 반경 밖 항목과 중복 ID를 제거한 뒤 거리순으로 표시합니다. 위치 변경 시 이전 응답은 무시합니다.
기본 10개로 잘리지 않도록 limit 20부터 시작하고 결과 수가 limit에 도달하면 두 배로 재조회합니다. 10240개까지 도달하면 반경 축소를 요청합니다.
명세에 페이지네이션과 limit 최대값이 없습니다. 서버에 숨은 최대값이 있다면 전체 조회를 보장할 수 없으므로 백엔드와 허용 범위/페이지 규칙을 확인해야 합니다.

서버 주소는 미제공입니다. `frontend/.env`의 EXPO_PUBLIC_API_URL 설정 후 재시작해야 실제 목록을 확인할 수 있습니다. 예시 시장 목록은 제거했습니다.
## 카카오 시장 이름 검색

사용자 제공 GET /markets/search/kakao?query=... 명세를 적용했습니다. query는 필수 시장 이름/키워드이며 위도·경도·반경 매개변수는 없습니다. 따라서 기존 GET /markets/nearby를 대체하는 현재 위치 기반 조회로 간주하지 않습니다.

시장 찾기 검색창에서 350ms 입력 대기 후 호출하고 입력 변경 시 이전 응답을 무시합니다. 검색어를 지우면 기존 주변 시장 목록으로 돌아갑니다. 400/500/502 및 잘못된 응답을 처리하며, 위치 권한이 없어도 키워드 검색 결과는 볼 수 있습니다. 카카오 REST 키는 백엔드에서 관리하고 프론트에 추가하지 않습니다.

응답 total_count는 카카오 API 원본 전체 개수이며 필터링된 documents 길이와 같다고 가정하지 않습니다. is_end=false라도 다음 페이지 요청 필드가 제공되지 않아 임의의 page를 보내지 않으며 검색어 구체화 안내를 표시합니다.

검색 결과 place_id는 카카오 장소 ID이며 내부 market_id로 사용하지 않습니다. 현재 결과 선택은 해당 좌표/시장명을 탐색 위치로 저장하고 주변 등록 시장을 조회하는 방식입니다. 이후 내부 market_id가 있는 시장을 선택해 가게 목록으로 이동합니다. 카카오 결과에서 바로 시장 가게 목록으로 이동하려면 검색 응답에 내부 market_id 또는 공식 장소-ID 매핑 API가 필요합니다. 임의로 이름을 비교하거나 숫자 변환해 매핑하지 않습니다.

개발 테스트 모드도 동일 경로의 예시 이름/주소 검색을 지원합니다. 검증 명령: node tests/market-search-api.test.cjs.

## 카카오 검색 결과 선택 동작 변경

검색 결과 선택은 더 이상 탐색 위치를 저장/수정하거나 주변 시장을 재조회하지 않습니다. 이 위치 주변 시장 보기 문구를 제거했습니다. 백엔드가 market_id(양의 Integer)를 제공하면 시장별 가게 목록으로 바로 이동합니다. market_id=null은 미등록 안내, 필드 누락은 연결 정보 미제공 안내를 표시하며 카카오 place_id를 내부 ID로 사용하지 않습니다. market_id는 현재 사용자 제공 상세 명세에는 없는 선택적 호환 필드로 백엔드 응답 확인이 필요합니다. 테스트 모드 응답에는 가상 매핑을 포함해 직접 이동을 확인할 수 있습니다.
