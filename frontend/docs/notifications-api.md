# 알림

공통 PageHeader의 알림 아이콘은 /notifications 화면으로 이동합니다. 알림 화면은 뒤로가기와 알림 제목을 사용하며 재진입용 알림 아이콘은 표시하지 않습니다. SafeAreaView 안에 헤더와 스크롤 목록을 배치하고 빈 목록 문구는 관심상품과 같은 방식으로 가로 중앙 정렬합니다.

사용자 제공 상세 명세와 api-spec.csv에 따라 Bearer 인증으로 GET /users/me/notifications?page=1&size=10을 호출합니다. 서비스 함수는 선택 is_read 필터도 지원합니다. 첫 페이지, 더 보기, 당겨서 새로고침, 빈 목록, 조회 오류와 재시도를 구분하며 화면 이탈/계정 변경 뒤의 응답은 버립니다.

알림을 누르면 PATCH /notifications/{notification_id}/read를 본문 없이 호출하고 200 응답의 notification_id/is_read=true/read_at/message를 검증한 뒤 읽음 표시를 바꿉니다. 중복 클릭을 막고 실패하면 읽지 않음 상태와 재시도 가능한 오류를 유지합니다. 동시에 목록을 새로 받아도 이미 읽음 처리 성공한 알림이 미확인 상태로 돌아가지 않도록 보관합니다.

notification_id/related_id는 현재 제공된 응답의 정수 ID를 검증합니다. 주요 유형 이외의 문자열 type은 일반 알림으로 표시합니다. related_id의 유형별 대상 API와 이동 규칙은 아직 확정하지 않아 예약/상품 화면으로 임의 이동하지 않습니다. 날짜에 시간대가 없으면 기존 앱과 동일하게 한국 시간으로 해석합니다.

개발 테스트 로그인에서는 계정별 알림 12개, 페이지/읽음 필터, 읽음 상태 유지와 다른 사용자 알림 403을 모의 처리합니다. 실제 로그인은 서버 API를 사용하며 서버 오류를 예시 알림으로 대체하지 않습니다. 실제 서버의 알림 발송·저장 동작은 별도 통합 확인이 필요합니다.


## 읽지 않은 알림 표시
공통 PageHeader의 종 아이콘 오른쪽 위에 읽지 않은 알림이 있을 때만 작은 빨간 점을 표시합니다. 화면 진입, 앱의 전경 복귀, 활성 화면에서 30초 간격으로 GET /users/me/notifications?page=1&size=1의 unread_count를 조회합니다. 알림 아이콘을 숨기는 화면에서는 별도로 조회하지 않으며, 겹치는 헤더 요청은 합칩니다. 푸시 알림 수신 기능을 추가한 것은 아닙니다.

모든 알림 목록 조회 결과는 계정별 공통 상태에 unread_count를 반영합니다. 읽음 처리에 성공하면 이미 미확인으로 알고 있던 알림만 한 번 차감하고 마지막 알림을 읽으면 점을 숨깁니다. 처리 중인 읽음 요청이나 이전 계정의 응답, 오래된 조회 응답이 수를 되돌리지 않도록 세대·변경 버전을 확인합니다. 다음 조회의 서버 값을 다시 적용합니다. 미확인 알림의 내용이나 토큰은 영구 저장하거나 로깅하지 않습니다.

알림 화면의 유형·본문·날짜·빈 목록·오류·버튼 글씨를 기존보다 2~3px 키웠습니다. 알림 헤더는 별도 크기 지정 없이 공통 PageHeader의 기본 크기(24px)를 사용합니다.
