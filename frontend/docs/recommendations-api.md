# 홈 추천 상품

사용자 제공 상세 명세에 따라 GET /recommendations를 Bearer 인증과 top_n=20으로 호출합니다. market_id는 서비스 함수의 선택 조건이며, 홈에서는 특정 시장으로 제한하지 않습니다. 요청에 위치 좌표나 반경 등 명세에 없는 필드는 추가하지 않습니다.

request_id/as_of/generated_at/rule_version/user_state/items 및 각 상품의 문자열 ID, 순위·점수·가격·거리·등록 시각을 검증하고 rank 순으로 표시합니다. 응답 오류를 예시 상품으로 대체하지 않으며 로딩·빈 목록·오류·재시도를 구분합니다. 화면 이탈/계정 변경 이후의 응답은 반영하지 않습니다.

카드 선택은 listing_id와 requestId를 공통 상품 상세로 전달합니다. 상세 화면의 기존 찜·예약 API가 request_id를 이어받으며, 카드에서 바로 찜할 때도 같은 request_id를 보냅니다. 일반 상품 경로는 기존처럼 request_id를 생략합니다. 추천 노출·상세 조회 이벤트는 사용자 제공 상세 명세에 따라 아래 기준으로 별도 POST합니다.

추천 응답에는 image_url/market_name이 없습니다. 이미지는 기본 영역으로 유지하며 시장명은 주변 시장 목록과 market_id를 문자열 그대로 정확히 비교해 확인되는 경우에만 표시합니다. market_3을 임의로 숫자 3으로 바꾸지 않습니다. 항상 이미지와 시장명을 표시하려면 백엔드가 해당 필드의 명세를 제공해야 합니다.

표시 거리는 응답 distance_km를 사용합니다. 위치 변경 시 재조회하지만, 추천 API에 위치 설정을 전달하는 계약이 없으므로 서버가 추천 거리에 사용하는 위치 정보의 출처와 변경 방식은 추가 협의가 필요합니다. 추천 응답을 휴대폰 좌표 기준으로 계산된 것으로 가정하지 않습니다.

개발 테스트 로그인은 같은 응답 구조의 모의 추천과 실제 테스트 상품 상세 ID를 사용합니다. 실제 로그인에서는 서버 API만 호출합니다. 백엔드/추천 AI가 미구현인 경우 서버 오류 안내가 표시됩니다.


## 노출·상세 조회 기록

POST /recommendations/events/impressions는 Bearer 인증으로 {request_id, events:[{event_id, listing_id, position, occurred_at}]}를 보내고 200 응답의 request_id/recorded_count/duplicate_count/message를 검증합니다. position은 rank 값의 추정이 아니라 실제 정렬된 카드 배열의 1부터 시작하는 화면 순서입니다.

카드·가로 스크롤·세로 스크롤의 실제 measureInWindow 좌표와 기기 창을 교차 계산해 카드 면적의 50% 이상이 보일 때만 노출로 판단합니다. 추천 응답 수신만으로 기록하지 않습니다. 탭 전환·화면 이탈·위치 설정 모달·앱 백그라운드·계정 변경 시에는 새 노출을 만들지 않습니다. 가로/세로 스크롤, 레이아웃/창 크기 변경, 화면 복귀 시 다시 확인합니다. 같은 추천 요청/상품은 앱 메모리 내에서 최초 한 번만 기록합니다.

POST /recommendations/events/views는 {request_id,event_id,listing_id,occurred_at}를 보내고 201 응답의 event_id/listing_id/event_type=VIEW/recorded_at/message를 검증합니다. 상품 클릭 때가 아니라 추천 경로로 열린 상품 상세가 해당 listing_id의 데이터를 로드하고 화면 포커스를 가진 뒤에 기록합니다. 로딩 실패·일반 상품 상세·레거시 미리보기 상품은 제외합니다. 같은 상세 화면의 재렌더링, 상품 데이터 새로고침, 가게 화면에서의 복귀에는 동일한 방문 ID를 사용해 중복을 만들지 않습니다. 새 추천 요청/상세 진입은 별도 방문 ID를 사용합니다.

분석 이벤트는 사용자 화면과 독립된 메모리 큐로 전송하며 실패해도 상세 진입/찜/예약을 막지 않습니다. 이벤트 시각은 ISO 8601 UTC입니다. 통신 실패·5xx·결과 형식 오류에는 1초/3초 후 최대 두 번 추가 전송하며, event_id와 occurred_at 등 원본 이벤트를 바꾸지 않습니다. 400/401/404/409는 재시도하지 않습니다. 로그인한 계정으로 수신한 추천 요청만 추적하며 다른 계정으로 이전 큐를 재전송하지 않습니다. 앱 종료 후 큐 복원과 영구 보관은 하지 않습니다.

개발 테스트 모드도 노출 중복 수와 상세 중복 반환, 동일 이벤트 ID의 내용 충돌 409 및 추천 요청 소유권을 모의 처리합니다. 실제 기기의 스크롤/네이티브 좌표 및 실서버 저장은 통합 확인이 필요합니다.
